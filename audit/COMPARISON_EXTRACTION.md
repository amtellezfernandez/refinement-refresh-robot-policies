# Comparison-level resource extraction protocol

Status: **planned, unexecuted pilot**, 2026-09-10. The adjacent `comparison_extraction_template.csv` contains a header only. No comparison or resource has been annotated in that template, and no independent-annotation result is claimed.

The legacy `pilot_audit.csv` is preserved as **unvalidated corpus-development material**. Its paper-level Q/P/U/NA labels mix sources, phases, denominators, and kinds of evidence. Do not import those labels into the new template, count them as completed annotations, or interpret `fully_reconstructable` as a validated judgment of reproducibility. Bibliographic checking in `BIBLIOGRAPHY_AUDIT.md` verifies identities and metadata, not those labels. Claims in the older README do not override this status.

## Unit of extraction

One row records **one annotator's assessment of one quantity for one arm of one named comparison, within one phase and accounting scope**. The baseline and intervention must be explicitly named; a paper is not a comparison. A quantity measured per call cannot be substituted for the quantity requested per episode. Put different clocks, phases, scopes, or denominators in different rows.

`comparison_id` identifies the frozen comparison contract. `quantity_id` identifies the same requested quantity across independent annotations; it includes arm, phase, unit, and denominator in its definition. `annotation_id` identifies the individual row. An adjudicated row gets a new annotation ID and retains the quantity ID. Preserve both original annotations. `parent_quantity_id` links a component to an aggregate so nested quantities are not counted twice.

CSV rules: UTF-8, comma-separated, with cells containing commas, quotes, or newlines enclosed in double quotes; internal double quotes are doubled. Empty numeric cells mean no numeric extraction. They never mean zero. Use an explicit measurement status. Timestamps use ISO 8601 UTC. Store task lists and derivation-input IDs as semicolon-separated values inside a cell; preserve a stable task ordering.

## Field dictionary and coding rules

| Fields | Required interpretation |
| --- | --- |
| `paper_key`, `source_url`, `source_version`, `source_sha256`, `source_artifact_type`, `accessed_utc` | Identify the actual evidence artifact. Use a versioned preprint, proceedings PDF, dated supplementary file, or repository commit. Hash the locally frozen file when available; if no file was captured, leave the hash blank and explicitly state the limitation in `coverage`. Artifact type is `paper`, `supplement`, `code`, `log`, or `author_webpage`. A bibliography update does not silently change the extraction source. |
| `comparison_claim`, `baseline`, `intervention`, `arm` | Record the original claim being examined and exact compared configurations, not a broader claim the annotator wishes the paper had made. `arm` is `baseline`, `intervention`, or `shared`. A shared row represents one shared cost, not one copy charged to each arm. |
| `task_suite`, `task_ids`, `task_population` | Identify the evaluated task/state population, task ordering, and selection. Distinguish an entire suite from a subset, training from test tasks, and demonstrations from evaluation episodes. Record unresolved population boundaries in `coverage`. |
| `checkpoint_id`, `checkpoint_revision`, `environment_revision` | Record the model/checkpoint and environment for this arm, including a fixed revision if supplied. Use `not_reported` when the exact revision is absent, not a guessed current revision. If the comparison changes the checkpoint, the two arm rows must reflect that change. |
| `outcome_estimand`, `outcome_source_locator` | State the outcome and weighting that the original claim concerns, with the source table/section. For example, a task-macro success average and an episode-pooled average are different estimands. This field locates outcome evidence; it does not declare equivalence or validate the outcome experimentally. |
| `accounting_scope`, `inclusion_boundary`, `phase` | Scope is `contrast_specific` or `lifecycle`. Declare included/excluded operations and amortization. Phase is `inherited_pretraining`, `acquisition`, `adaptation`, `tuning`, `evaluation`, `deployment`, or `cross_phase`. Use cross-phase only if the source cannot be split; explain it. Different scopes use different quantity IDs even when based on the same passage. |
| `resource_name` | Name exactly what is requested: e.g. new simulator transitions, operator person-hours, policy generations, internal solver evaluations, device elapsed time, outer wall time, or retained bytes. Avoid ambiguous labels such as “compute” without a quantity definition. |
| `source_locator`, `evidence_passage` | Give page/section/table/row/appendix, code path and line/commit, or log record IDs. Record a short exact passage sufficient to support the extraction, or identify a numeric table cell with its row and column. A title or abstract is not evidence that a resource is absent. For unknowns, list the relevant sections/artifacts actually searched. |
| `evidence_mode` | `author_reported`, `artifact_recomputed`, or `none`. A measured number copied from a paper remains author-reported; it is not an independent measurement by this project. Artifact recomputation requires a named command/script and frozen inputs in `derivation`. |
| `numeric_value`, `unit` | Use a scalar decimal value without formatting separators, together with the exact unit. Represent separate endpoints or statistics with separate quantity IDs and describe their meaning. Preserve the original reported value; any normalized value is a separate derived row. Do not invent an exchange rate between calls, FLOPs, device time, energy, human time, or money. |
| `denominator_name`, `denominator_value`, `denominator_unit` | State what work the value covers: e.g. one training recipe, 40 tasks, 500 attempts, or one neural generation. A value without an identifiable denominator cannot support a normalized comparison. For an absolute total use `denominator_name=declared_scope_total`, value `1`, and the scope's unit. This encoding must not conceal a missing scope. |
| `aggregation` | `sum`, `maximum`, `snapshot`, `outer_interval`, `distribution`, `rate`, or `not_aggregatable`. Sum only compatible, nonoverlapping counts/costs. Peak memory uses a maximum; persistent storage has a snapshot boundary. Concurrent or nested durations are not summed to obtain wall time. |
| `applicability`, `applicability_reason` | `applicable`, `not_applicable`, `outside_scope`, or `undetermined`. Give a claim-specific reason. Missing reporting is not proof of non-applicability. A shared inherited resource can be outside a marginal contrast while remaining applicable to lifecycle cost. Keep undetermined judgments unresolved rather than removing them from a denominator. |
| `measurement_status`, `unknown_reason` | Status is `measured`, `derived`, `unknown`, or `NA`. Measured means the source reports a direct count/measurement; derived requires explicit inputs and arithmetic. Unknown applicable quantities have blank numeric values and a reason: `not_found_in_checked_sources`, `ambiguous_unit`, `ambiguous_denominator`, `ambiguous_boundary`, `source_inaccessible`, `conflicting_evidence`, or `undetermined_applicability`. `NA` is reserved for reasoned non-applicability or exclusion, not unreadable sources. |
| `cost_origin`, `shared_in_contrast` | Origin is `inherited`, `new`, `mixed`, or `undetermined`; sharing is `shared`, `not_shared`, or `undetermined`. Record what is reused and whether both arms incur the same quantity. Shared is not synonymous with zero, negligible, or free. Split mixed costs when evidence permits. |
| `coverage`, `attempts_included`, `exclusions` | State which operations, successful/failed/aborted attempts, warm-up, resets, data collection, tuning, rendering, and overhead are included. `attempts_included` is `all`, `successful_only`, `other_subset`, `not_applicable`, or `unknown`. Account for exclusions before interpreting cost per attempt or per success. |
| `derivation`, `derivation_inputs`, `uncertainty` | Give the expression, input quantity IDs, assumptions, and any conversion. Derived totals stay unknown if a required input is unknown. Cost per success is undefined when successes equal zero. Preserve reported uncertainty and its sampling unit; do not manufacture confidence intervals from unavailable sample sizes. |
| `annotator_id`, `annotation_round`, `annotated_utc`, `adjudication_status`, `adjudicator_id`, `adjudication_note` | Use pseudonymous annotator IDs; round is `independent_1`, `independent_2`, or `adjudicated`. Adjudication status is `not_reviewed`, `agreed`, `resolved`, or `unresolved`. Adjudication records the substantive disagreement, evidence, and decision. Two LLM passes are not independent human annotation. |

## Six-comparison pilot

This is a feasibility/measurement-utility pilot, not a systematic review or prevalence estimate. Its six candidate source families are **VLA-RL, CO-RFT, E2HiL, Hi-WM, FLASH, and A2C2**, spanning policy adaptation, feedback/acquisition, and deployment. These are a purposive starting frame, not six completed or already validated contrasts. No paper-level disclosure score is assumed.

1. **Freeze one original contrast per source.** A coordinator who does not score resource completeness selects a comparison directly supporting a main claim, naming the exact table/figure, baseline, intervention, checkpoint, tasks, outcome, source version, and included phases. Use a documented rule such as the first main-text quantitative comparison supporting the named claim, rather than selecting the worst reporting or largest gain. Where the rule is ambiguous, resolve and document it before extraction. If the source is inaccessible or no eligible contrast exists, record that failure; do not quietly substitute another paper after seeing labels.

2. **Predeclare the requested quantities.** Before numeric extraction, define the minimal resources needed for each original claim, with units, denominator, and reasons. Separately define any lifecycle extension. Two human annotators independently assess applicability and boundary ambiguity. Preserve the initial decisions, reconcile the scope, and freeze the resulting six contracts before the independent value-extraction round. This prevents each annotator's missingness score from measuring a different checklist.

3. **Extract independently from frozen evidence.** The same two annotators separately fill the rows using the same source bundle and quantity requests, without viewing the other's values or the legacy codes. Record available author-reported numbers and explicit derivations; use unknown for unavailable evidence. Time extraction effort per comparison outside the resource ledger, because annotation labor is a property of this pilot, not of the cited method. No new author contact is required for this pilot.

4. **Adjudicate with the original rows retained.** Report agreement separately for applicability, measurement status, unit/denominator, numeric transcription, and derivation. Report counts and the kinds of disagreement at comparison and quantity level. Do not treat many resource rows from six sources as independent papers or make a stable inter-annotator-reliability claim from this small pilot. Keep unresolved items and access failures visible.

5. **Evaluate recoverability, not paper quality.** For each contrast ask whether the prespecified quantity is recoverable from the declared evidence, unknown, or internally inconsistent. A measured/derived number is recoverable only if scope, units, denominator, coverage, and every required input are resolved. Compare what a score-only view, a score-plus-reported-proxy view, and the extracted contract support. Count changed interpretations using the six comparisons as the analysis units; allow the result that richer accounting changes no supported interpretation. Missing lifecycle cost must not invalidate a contrast where it cancels or is irrelevant.

6. **Release a bounded feasibility report.** Publish the frozen source manifest/contracts, raw and adjudicated rows, access limitations, extraction time, adjudication log, and all six comparison judgments. Quote only short necessary passages and use locators for longer evidence. Label every absent or unfinished comparison explicitly. A larger preregistered corpus is justified only after the pilot demonstrates usable definitions; no finding from that larger study is promised here.

The six-comparison pilot has not been run. A populated CSV, two independent human annotations, and adjudication records are required before reporting pilot results.
