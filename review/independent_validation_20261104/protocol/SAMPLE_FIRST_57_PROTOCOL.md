# Sample-first diagnostic: 57 archived attempts (alternative to frozen Stage 0–1–2)

## Motivation and scope

The author prefers to test the frozen 57-attempt stratified sample before
the full 80-state reset survey. This mode tests ONLY the 57 archived primary
attempts (R22 and R25), on the declared arm64 macOS host, using the existing
frozen sample selection. It does **not** constitute a completed Stage 0,
a validated 320-attempt confirmation, or a release to replay more attempts.
No archived results have been inspected on this alternative host.

The prior 57 IDs, 29 strata, salt, archived 1,120-bundle population, protocol
pins, `1e-6` absolute reset-state tolerance, rendering and 57-attempt outcome
criteria are unchanged. The 57 attempt identities and selection SHA-256 are
`3ffe84b0ef2d055a6c22667406c9d8eca370bf66ab7999c46e99a7114f73df56`.
The complete 1,120-bundle byte hash is
`99587b7e3ea594572f18ee3b933109eaf57dfa0ce4cc74deea83b3bc1b43f372`.

## Procedure: sample reset screen, then 57 action replays

1. Before launching a simulator, require a dedicated `release.json` bound to
   **this** protocol file, `execution_mode = "sample_first_57_v1"`,
   `scope = [1]`, the exact frozen bundle and sample manifest bytes, and
   all executable and amendment SHA-256 digests. A general Stage 0 or
   Stage 0–2 release does **not** authorize this mode.
2. Write the counted-run identity, release hash, host, interpreter/runtime
   versions, original archive, 57 frozen identities and protocol hash to a
   new output directory, before the first reset.
3. Run **reset-only screening for each of the 57 sampled attempts** using the
   exact pinned reset procedure: seed, hard reset, official init state, ten
   settled dummy actions, relative control. Compare the complete post-settle
   state to the archived state at max-abs tolerance `1e-6`. This produces
   a 57-row screen, including observed exact/tolerance agreement. There is
   no execution of archived policy actions during this screen.
4. If **any** sample reset is mismatched, malformed, nonfinite or fails to
   reproduce, report `FAIL_SAMPLE_RESET` and stop. Do not inject the
   archived state to hide a reset mismatch, loosen the threshold or select a
   replacement sample after seeing results. The next action would be a
   separately specified x86_64 Linux replication.
5. Only if every sampled reset passes, replay the 57 attempts from their
   reconstructed resets, **without loading SmolVLA**. As in the frozen
   protocol, run the primary reset-path arm twice for within-host determinism
   and the archived-state injection arm once as a secondary diagnostic.
   Each individual replay is separately checked against the same `1e-6`
   starting-state threshold before any archived action is applied.
6. Compare each replayed binary success and first-success tick against the
   corresponding archived label/trace. Preserve per-attempt outputs,
   disagreements and errors. The exact frozen verdict table and tolerance
   apply to this sample only. Any scientific disagreement or failure yields
   nonzero process exit and stops this line pending review.

## Interpretation

Even if all 57 outcomes match, report ONLY "sample replay internally consistent
under the sampled reset screen", never "the original 80-state Stage 0 passed",
"320 attempts independently confirmed", or "full instrument validated".
The 57 were selected using the **archived outcomes** for stratification, so
this is a diagnostic sample, not a fresh unbiased performance estimate.
The code does not independently verify which actions were generated by
SmolVLA, nor whether BDDL goals align with human task success.

The original 80-state Stage 0 and 320-attempt Stage 2 remain *unrun*. The
frozen original protocol is preserved verbatim and may later be run using a
separate release. There is no automatic promotion from this diagnostic to
the original protocol's full-confirmation stages.
