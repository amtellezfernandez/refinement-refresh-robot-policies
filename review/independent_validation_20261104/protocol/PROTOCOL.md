# Model-free replay of the SmolVLA confirmation evidence: frozen protocol

Status: **FROZEN, NOT APPROVED, NOT RUN.** Prepared 4 November 2026 on branch
`warren/independent-replay-validation` (local). No archived action has been replayed.
Execution requires Alba's written approval of this exact file (section 12).

## 1. Question

Do the archived outcome labels of the confirmation attempts follow from the archived
initial states and action streams when those actions are replayed, without any policy,
in a separately installed, version-matched LIBERO environment?

## 2. What this can and cannot establish

Can: that each archived success/failure label, and its exact success tick, is what the
LIBERO task predicate yields for the archived action stream from the archived start, in a
separate install, process, machine and reset implementation. Together with the hash
checks, that is evidence against logging, aggregation, labelling and dispatch errors.

Cannot: that SmolVLA produced those actions (no model is run); that the BDDL predicate
matches a human judgement of task completion (the same predicate code is used, by design);
anything about real robots, asynchronous execution or other checkpoints. Replay also has
limited power against a fully consistent forgery of the action stream (section 9).

## 4. Population and sampling

Population: the 1,120 canonical confirmation attempts (7 configurations × 8 tasks × 10
states × 2 seeds), canonical attempt per planned run chosen by phase precedence
confirmation > primary_deadline > continuation_partial > continuation_rest. The two
excluded repeats are not replayed in Stages 1–2. They may be replayed descriptively in
Stage 3.

Stage 1 frame: the 320 primary attempts (h2_d2 = selected, h2_d5 = comparator).
Strata: task × condition × archived outcome. 29 strata are non-empty.
Draw: within each stratum, order by sha256(`rrrp-replay-stage1-20261104|` + planned_run_id)
and take the first 2. This gives 57 attempts. The sample was drawn and hashed before any replay.

Stage 2: all 320 primary attempts. Stage 3 (optional, descriptive): the 800 secondary attempts.

## 5. Procedure

Per attempt:
1. Validate input statically: action hashes, dtype and shape (float32, 7), contiguous ticks,
   stream hash against the separate episode record, label vs per-tick flags, horizon,
   termination reason, initial-state hash, and keyed environment seed.
2. Hard reset, in the same order as the pinned wrapper: seed Python and NumPy with
   environment_seed, then `env.seed`, `env.reset()`, `set_init_state(official init_states[id])`,
   then 10 no-op settle steps `[0,0,0,0,0,0,-1]`, then `use_delta = True`. Rendering is on at
   360×360. Render-off physics was identical on all 20 fixtures, but the confirmatory run renders.
3. Compare the post-settle state with the archived `initial_state`, exact and max-abs.
4. Apply every archived float32 action in archived order. After each step, evaluate
   `check_success()`. Record per-tick flags, the first success tick, terminal predicate
   values and the terminal state hash.
5. Run two arms. **reset_path is primary.** inject is secondary: same as reset_path, but the
   archived post-settle state is written over the replay's state after step 2. The
   gripper and controller hidden state from settling is kept.

Hidden state that is not in the archived 110/79-value state, and is regenerated by
step 2 rather than injected: the Panda gripper's `current_action`, which integrates 0.01 per
step; OSC `goal_ori`, which is updated only on a non-zero rotation delta; and robosuite step bookkeeping.

## 6. Stages, run identity and gates

Stage 0, reset fidelity with no actions: all 80 task-states.
Stage 1: the 57-attempt sample. reset_path runs twice for determinism; inject runs once.
Stage 2: the 320 primary attempts, reset_path plus inject.
`run_protocol.py` starts a stage only if the previous stage's verdict permits it.

```selection-and-gates
counted_run: the first run_protocol.py execution started under the approved release on the declared host; its OUT_DIR path, start time and release sha256 are written to the run log before Stage 0 begins
rerun_policy: none for counting. A crash or host failure makes that stage UNINTERPRETABLE; a later execution is reported as a separate run and never replaces the first
post_data_free: NONE for Stages 0-2; Stage 3 inclusion is optional and descriptive only
gate: release | archived bundles refused without an approved release bound to this file's sha256 | enforced_at: replay/replay.py:206 | before: any archived replay | qualified_on: matching APPROVED release -> pass (runs); missing, wrong-hash or PENDING release -> fail (exit 5; test_harness G, 4/4)
gate: stage0_reset | every task-state max-abs diff <= RESET_TOL 1e-6 | enforced_at: replay/run_protocol.py:176 | before: Stage 1 | qualified_on: clean fixtures -> pass (PASS_EXACT, drill A); one start forged by 1e-3 -> fail (FAIL_RESET, exit 6, Stage 1 absent, drill B)
gate: stage1_pass | Stage 1 verdict in PASS_EXACT, PASS_WITHIN_TOLERANCE, PASS_OUTCOME_ONLY | enforced_at: replay/run_protocol.py:185 | before: Stage 2 | qualified_on: clean fixtures -> pass (Stage 2 runs, drill A); planted mislabel -> fail (DISAGREEMENT, Stage 2 absent, drills D and E)
selection_risk: material
selection_anchor: the release file's sha256 and the run log line written before Stage 0, both committed before any Stage 1 result is read
multiple_executions: a second execution of the same stage is reported alongside the first and invalidates neither the reporting of the first nor substitutes for it; if two executions disagree the stage is UNINTERPRETABLE
stop_on_confirmation: if Stage 2 is PASS_EXACT or PASS_WITHIN_TOLERANCE, the default is to CLOSE the replay line and report; no further replay variants
verdicts: PASS_EXACT, PASS_WITHIN_TOLERANCE, PASS_OUTCOME_ONLY, CHAOTIC_INCONCLUSIVE, DISAGREEMENT, ARCHIVE_DEFECT, FAIL_RESET, UNINTERPRETABLE
review_rounds_max: 2
```

## 7. Outcomes and criteria (fixed before any replay)

Primary outcome: per-attempt agreement between the replayed outcome and the archived label
in reset_path mode. Secondary outcomes: exact success-tick agreement; the inject arm;
replay-derived counts for h2_d2 and h2_d5. These must equal 139/160 and 122/160 if every
outcome agrees.

Numerical tolerance: `RESET_TOL = 1e-6`, the maximum absolute difference over all flattened
state components. It was set before any archived comparison, as a value orders of magnitude
above double-precision rounding over 10 settle steps and below 1 µm or 1 µrad. It is a judgement, not a
measured threshold.

```verdict-table
dim: integrity=clean|defect
dim: reset=exact|within_tol|fail
dim: determinism=stable|unstable
dim: outcome=all_agree|mismatch_reachable|mismatch_unreachable
dim: ticks=all_agree|some_diverge
rule: integrity=defect, reset=*, determinism=*, outcome=*, ticks=* -> ARCHIVE_DEFECT
rule: integrity=clean, reset=fail, determinism=*, outcome=*, ticks=* -> FAIL_RESET
rule: integrity=clean, reset=exact, determinism=unstable, outcome=*, ticks=* -> UNINTERPRETABLE
rule: integrity=clean, reset=within_tol, determinism=unstable, outcome=*, ticks=* -> UNINTERPRETABLE
rule: integrity=clean, reset=exact, determinism=stable, outcome=mismatch_reachable, ticks=* -> DISAGREEMENT
rule: integrity=clean, reset=exact, determinism=stable, outcome=mismatch_unreachable, ticks=* -> DISAGREEMENT
rule: integrity=clean, reset=within_tol, determinism=stable, outcome=mismatch_reachable, ticks=* -> CHAOTIC_INCONCLUSIVE
rule: integrity=clean, reset=within_tol, determinism=stable, outcome=mismatch_unreachable, ticks=* -> DISAGREEMENT
rule: integrity=clean, reset=exact, determinism=stable, outcome=all_agree, ticks=some_diverge -> PASS_OUTCOME_ONLY
rule: integrity=clean, reset=within_tol, determinism=stable, outcome=all_agree, ticks=some_diverge -> PASS_OUTCOME_ONLY
rule: integrity=clean, reset=exact, determinism=stable, outcome=all_agree, ticks=all_agree -> PASS_EXACT
rule: integrity=clean, reset=within_tol, determinism=stable, outcome=all_agree, ticks=all_agree -> PASS_WITHIN_TOLERANCE
```

Mismatch adjudication applies only when Stage 0 passed within tolerance rather than exactly. Each
mismatching attempt is re-run 10 times with N(0, 1e-9) noise on the non-zero components of
the archived start, using seed 20261104 + stage. If the archived outcome appears in any draw,
the result is "reachable". Under an exact Stage 0, any mismatch is a DISAGREEMENT.

Unreplayable or reset-mismatched attempts are counted, never dropped. Their stage is
UNINTERPRETABLE, and its denominator is reported.

## 8. Predictions

- Stage 0: **no prediction about bitwise equality.** The original host was x86_64 Linux
  (glibc 2.39), and the replay host is arm64 macOS. Predicted: max-abs ≤ 1e-6 for all 80. This is exploratory.
- Stage 1 and Stage 2, if Stage 0 is exact: all outcomes and ticks agree (PASS_EXACT), and
  replay-derived counts are 139/160 and 122/160. If Stage 0 is within tolerance: all outcomes agree, and
  some ticks may diverge on near-miss attempts. The fixtures show a single 1e-4 action
  change can move a success tick in 1/15 trajectories.
- Value asymmetry: agreement is the expected result and validates the recording path,
  modestly. A DISAGREEMENT is the informative outcome.

Observations that would contradict the account of the instrument:
1. An outcome mismatch under an exact Stage 0.
2. The same attempt giving different terminal states in two replays on one host.
3. A replayed success at an earlier tick than the archived success, which would mean
   the original runner missed a success.
4. A failure that succeeds in replay at any tick.
5. The inject and reset_path arms disagreeing while Stage 0 is exact.

## 9. Negative controls (qualified on synthetic fixtures, 4 November 2026)

| # | Detects | Method | Result |
|---|---|---|---|
| 1 | label inconsistent with flags | flip label only | INPUT_INVALID |
| 2 | false success, consistent records | last flag + label set True on a failure | OUTCOME_MISMATCH |
| 3 | false failure, consistent records | success padded to horizon with valid no-ops | OUTCOME_MISMATCH (3/3) |
| 4 | truncation | drop 5 actions, stale or consistent | INPUT_INVALID |
| 5 | altered action | stale hash | INPUT_INVALID |
| 6 | missing step | tick gap, or renumbered with a stale stream hash | INPUT_INVALID (1 + 5/5) |
| 7 | wrong start | wrong state id, consistent seed; start forged ±1e-3 | RESET_MISMATCH |
| 8 | metadata | seed, horizon, task, dtype, missing field | INPUT_INVALID / RESET_MISMATCH |
| 9 | duplicates | same bundle; same stream under a new key | DUPLICATE |
| 10 | harness mutation | validation disabled; outcome comparison disabled | the dependent detections go blind |

Limits of power, measured on 15 known-success fixtures (not gated):

- A fully consistent deletion forgery (step removed, renumbered, every hash rewritten) was
  detected in **2 of 15** cases.
- A consistent one-tick action change was detected in 0/15 at 1e-7, 1/15 at 1e-4 and 1e-2, and 5/15 at 0.3.
- Replay alone therefore cannot authenticate action streams. Their protection is the hash
  chain plus two separately written records.

Untested branch: CHAOTIC_INCONCLUSIVE, where the archived outcome is reachable under perturbation, has no fixture.
